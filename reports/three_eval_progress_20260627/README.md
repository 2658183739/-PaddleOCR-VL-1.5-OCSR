# 三评测集当前结果与技术路线说明

日期：2026-06-29

## 结论

现在确实比 V2-1 原始结果好了一些。提升主要来自候选选择、路由、轻量重排和局部裁剪，不是直接大改主 VLM。

当前瓶颈也很明确：selector 已经有收益，但候选池 oracle 还没高到可以“强一倍”。所以后面更该补候选，而不是继续盲堆后处理。

主模型只使用 PaddleOCR-VL-1.5，不切换到其它 VLM。

## 三个评测集

下面是当前三套评测的总览。`baseline` 是原始基线，`stable` 是当前稳健值，`best` 是本地最优，`oracle` 是现有候选池上限。

| 面板 | N | baseline | stable | best | oracle | 说明 |
| --- | ---: | ---: | ---: | ---: | ---: | --- |
| 1344 combined | 1344 | 0.267113 | 0.350446 | 0.354167 | 0.387649 | 三个面板合并后的总览 |
| canonical_smiles_main_v1 | 767 | 0.370274 | 0.458931 | 0.461538 | 0.494133 | 主 OCSR 面板，覆盖 printed + real_world |
| weak_domain_v2 | 577 | 0.129983 | 0.206239 | 0.211438 | 0.246101 | 弱域诊断面板，覆盖 handdrawn / photo-scan / edu / long-stereo |
| region_panel_770 | 770 | 0.384416 | 0.437662 | 0.440260 | 0.527273 | 区域路由诊断面板 |

结论很简单：

- 三套都比 baseline 好了。
- 主集提升最稳，弱域提升幅度最大，但 oracle 仍偏低。
- region panel 的上限最高，说明候选池还有空间，但不是 selector 单独能吃完的。

## 技术路线

技术不止三条，只有评测集是三部分。当前相关技术线可以分成下面几类。

1. 单候选 reward head

   直接给每个候选打分，取分最高的候选作为输出。这个是当前最稳的保底线，也是现在最该保留的主方案。

2. 分组路由

   按 `source / difficulty / task_type` 之类的元信息切换不同的选择器。它在本地能拿到更高分，但有过拟合风险，不能把 local best 当成最终结论。

3. listwise / pairwise reward head

   用同一张图的多个候选做排序学习。它适合做 smoke train，能验证“候选选择”这条路有没有增益，但目前还没稳定替代主线。

4. 候选扩展与区域裁剪

   目标不是把 selector 训得更激进，而是把候选池补全。对 `document_embed`、`journal_fig`、`multi_grid`、中文考试整页这类样本，这条线比单纯加大模型更重要。

5. `chem_light` / reward policy rerank

   轻量化学规则重排，主要修正明显非法或结构不合理的候选。小面板上有时能涨分，但全量不稳定，所以更适合当局部工具，不适合全量强制开启。

6. head ensemble

   把多个 reward head 做平均或组合。它能稳定性更好一点，但目前没有刷新 strict CV 的最好结果，所以不是主方案。

## 现在该保留什么

- 保留当前稳健 reward 路线，不回退到原始 baseline。
- 保留候选保存，别只看单输出。
- 保留区域裁剪和候选扩展，但只在弱布局类样本上重点用。
- 不要继续盲目扩大弱布局 crop 变体，先把候选源补齐。
- 如果后面要做后训练，优先做 candidate-choice / preference 方向，不直接改主 VLM。

## 方法细节

下面把每条技术线的思路、优化目标、收益和原因说清楚。

| 部分 | 怎么想 | 优化什么 | 为什么这么做 |
| --- | --- | --- | --- |
| 单候选 reward head | 先利用现有候选池，不重做主模型 | 提高 selected 候选命中率 | 候选池里已经有不少正确答案，先把“选错”变成“选对”，成本最低、收益最快 |
| 分组路由 | 不同来源/难度/任务的错误分布差异很大 | 让不同组用不同选择器 | 一个全局策略会把强组和弱组一把抓，分组后能把有限增益集中到短板上 |
| listwise / pairwise reward | 用候选间偏好而不是绝对标签学习 | 学会更稳定的排序 | 比起直接改主模型，这条线更适合 smoke train，也更容易验证“模型到底会不会选” |
| candidate expansion / crop | 先补候选，再谈重排 | 提高 oracle 上限 | 如果正确答案根本没进候选池，selector 再强也没用；所以先补召回 |
| `chem_light` / rerank | 先修明显非法/不合理候选 | 降低语法型错误 | 这类规则便宜、可解释，适合作为 fallback，但不适合硬套全量 |
| head ensemble | 用多个 head 抵消单模型波动 | 降低 seed 方差 | 小面板上能提升稳定性，但通常不改变候选池上限，所以不能替代主路线 |

这也是为什么当前不直接“大改 VLM 主模型”。主模型一旦动大，训练成本和回退风险都高，而现在最缺的不是表达能力本身，而是候选召回、候选选择和弱域局部路由。

## 训练集分布为什么这样

当前训练分布不是按数量平均，而是按“基础分布 + 真实场景权重 + 长尾补充”来定。

| 训练部分 | 设定 | 原因 |
| --- | --- | --- |
| `uob` / `uspto` | repeat 1 | 这是 printed / patent-style 的稳定基座，不能被稀释掉 |
| `real_world` | repeat 5 | 真实拍照、扫描、页面嵌入、考试图是主要失分来源，样本少但必须加权 |
| `molgrapher_synthetic` | repeat 2 | 用来补复杂结构、视觉扰动和长尾形态，但不能压过真实分布 |
| `uspto30k_*` | 每类 cap 1500 | 这些数据太干净，量太大会把模型拉回“只会识别干净图”的方向 |

这个分布的基础，不是总量，而是三件事：

1. 当前 baseline 的错误分布。
2. 目标部署场景里的真实样本分布。
3. 标签可信度和来源稳定性。

更好的分布不是简单重算比例，而是按“错误率 + 候选 oracle gap + 来源可信度”动态调权。比如某一类样本如果错误率高、且候选池有潜力，就应该加权；如果样本很干净但对最终任务帮助有限，就不该无限放大。

## 评测集分布为什么这样

评测集不是为了“平均”，而是为了同时覆盖主分布和弱点。

### `canonical_smiles_main_v1`

767 条，按 `decimer 150 + uob 200 + uspto 200 + real_world 217` 组成。

这么分的原因是：

- `uob` / `uspto` 代表稳定 printed 主分布。
- `decimer` 代表手绘/风格变化。
- `real_world` 代表真正的部署场景，故意保留更多，避免只看干净图。

这个集合的作用是看“主能力有没有站住”。它不是极端困难集，而是主赛道的代表性评估。

### `weak_domain_v2`

577 条，按 `decimer_handdrawn 150 + real_world_photo_scan 212 + edu_exam 153 + long_or_stereo 62` 组成。

这么分的原因是：

- 这几个类都是当前最弱、最容易暴露问题的地方。
- `edu_exam` 和 `photo_scan` 贴近真实比赛中的高风险样本。
- `long_or_stereo` 数量少，是因为高质量样本难收，但诊断价值很高。

这个集合不是为了反映平均分布，而是为了把短板挑出来。

### `region_panel_770`

这个面板主要用来比较路由、裁剪和候选选择，不是主 leaderboard 口径。

它的数量来自现有可用样本和路由诊断需求，重点是让不同策略在同一套区域场景下可比。它对 `document_embed`、`journal_fig`、`multi_grid` 这类局部问题特别敏感，所以适合做策略回归。

如果重新设计评测集，更好的做法是：

- 诊断集用 stratified / balanced 分布，保证每个难点都有足够样本。
- 主评估集保留真实混合分布，反映实际部署权重。

## 标签清洗与人工复核

目前测试集标签清洗主要基于规则，这个做法是有效的，但不够完整。

### 规则为什么有效

规则清洗的作用是把明显不该进主评测的样本先剔掉，尤其是：

- 非单分子目标。
- 反应式、多分子、chemfig、`ssml_normed` 之类不是 canonical SMILES 的标签。
- 空标签、坏路径、坏图、重复样本。
- 目标区域不明确、无法稳定对应到单一分子的样本。
- 训练集和评测集之间的泄漏样本。

它的有效性体现在两点：

- 能稳定减少噪声和歧义样本，让评测口径可复现。
- 能把“明显错误”先挡掉，避免标签污染把结论带偏。

### 规则的边界

规则只能处理“显式错误”，处理不了“语义边界”。

比如：

- 图里其实有多个可能目标，但规则未必知道该选哪个。
- 标签形式是合法 SMILES，但与图中目标区域可能不完全一致。
- 教育图、页面图、局部裁剪图里，目标定位可能需要人工判断。

所以规则清洗是底座，不是最终答案。

### 建议的人工检查流程

官方建议是对的，应该加人工复核，而且要有明确流程，不是随便看两眼。

建议这样做：

1. 规则先做 hard filter，保留可疑样本单独列出。
2. 对以下样本人工复核：多候选冲突、页面图、教育图、长分子、手绘、multi_grid、document_embed。
3. 评测集建议尽量接近 100% 人工确认；训练集至少对高风险子集做全量复核，其余做抽样检查。
4. 复核时记录原因码，例如 `multi_target`、`ambiguous_region`、`label_mismatch`、`bad_image`、`leakage_suspect`。
5. 双人复核只用于争议样本，不要把所有样本都人工过一遍，成本太高。

如果要对外回复官方，可以这么说：

“当前清洗流程已经能稳定剔除明显无效和泄漏样本，保证主评测可复现；但对于目标区域不明确、页面嵌入、多分子边界样本，纯规则仍不足以完全保证语义正确性，因此我们将增加人工抽检和争议样本复核，作为规则清洗的补充。”
