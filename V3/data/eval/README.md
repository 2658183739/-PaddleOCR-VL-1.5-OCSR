# OCSR 正式评测集说明（提交版）

> **V3 final 口径说明：** 本文件保留早期“统一评测集”组织方案的历史说明。V3 最终实验采用 `dev_legacy_core_strict` 753 条、`dev_legacy_region_strict` 754 条、`wild_strict_v3` 301 条、`wild_strict_scaffold_novel_v3` 134 条和 `wild_symbolic_v3` 460 条的分角色设计；最终构建过程、实际目录和去泄漏证据以项目根目录的 `EVAL_DATASET_CONSTRUCTION_REPORT_zh.md` 为准。本文件中的旧总量不得作为 V3 locked final test 的样本量。

## 1. 数据集定位

本目录为当前项目用于提交的 **OCSR 正式评测集（Evaluation Collection）**。

设计目标如下：

1. 评测集总量充足，能够支撑稳定评估；
2. 评测数据尽量来自真实或公开可追溯来源，避免 synthetic-heavy 风险；
3. 主任务与教育场景子任务边界清晰，保证结果解释可信；
4. 目录结构、标注文件、质量控制说明和统计信息完整，便于复核与复现。

---

## 2. 总规模

- **总样本数：3758**

从数量上看，本评测集已经显著高于“300 条以上较稳、1000 条以上更具说服力”的常见经验门槛，可以支持较稳定的模型对比分析。

---

## 3. 评测集组成

本评测集由两个**正式子基准**构成：

### 3.1 主 OCSR 核心基准：`canonical_smiles_main_v1`

- 样本数：**767**
- 任务目标：`canonical_smiles`
- 适用场景：标准有机化学结构式 OCR 主任务
- 来源构成：
  - `decimer`：150
  - `uob`：200
  - `uspto`：200
  - `real_world`：217

该子基准用于输出当前项目的**主分数**，其目标是统一、单一、可解释的 OCSR 主任务评测。

### 3.2 教育场景专项子基准：`edu_chmec_ssml_normed_test_v1`

- 样本数：**2991**
- 任务目标：`ssml_normed`
- 适用场景：教育场景下的手写/教学化学结构图识别
- 来源构成：
  - `edu_chemc`：2991

该子基准用于体现教育场景的专项覆盖能力，**不直接并入主 OCSR 核心分数**，而是作为单独结果层进行解释。

---

## 4. 为什么采用“统一提交、分子基准解释”的结构

本项目希望同时满足两类目标：

1. 主任务上有一个标签口径明确、结果可解释的标准 OCSR 基准；
2. 在教育场景上体现更高的数据规模、场景稀缺性和真实应用价值。

如果将两类子任务直接混成一个单一总分，会带来两个问题：

- `canonical_smiles` 与 `ssml_normed` 并非同一标签空间，混算后结论不清晰；
- 评审难以判断模型究竟是在标准 OCSR 上更强，还是仅在教育场景格式上更适配。

因此，本提交版采用：

- **一个统一评测集目录**；
- **两个正式子基准**；
- **分别报告主任务结果与教育场景结果**。

这种组织方式既能保证规模和多样性，又能保证结论可解释。

---

## 5. 真实性与来源边界

本评测集的构建遵循以下原则：

1. 主评测层尽量使用公开可追溯、任务边界清晰的真实/公开基准来源；
2. 教育场景层使用本地整理的 EDU-CHEMC 测试子集；
3. 不将 `EDU-CHEMC / Markush / mechanism-style` 等非主任务标签口径数据直接混入主 OCSR 分数；
4. 不在主评测集目录中保留实验性候选层、用户自采临时目录或垃圾文件；
5. 评测主目录仅保留实际提交需要的内容：图像、标注、说明、统计与质控文档。

## 7. 主要优点

### 7.1 数据规模充足
总量 3758，已明显超过小规模 benchmark 的水平。

### 7.2 类型方差较大
包含：

- 真实手绘结构图
- 公共 printed benchmark 图像
- 真实世界补充图像
- 教育场景手写/教学结构图

### 7.3 难度分层明确
主任务层中包含 `medium / medium_hard / hard`，真实补充层中又包含 `photo / scan / page_level / degraded_scan / handwritten / journal_fig / multi_grid` 等不同场景标签。

### 7.4 主任务口径清楚
标准 OCSR 主任务统一为 `canonical_smiles`，不会因为混入其他标签体系而破坏主分数解释。

### 7.5 支持专项扩展分析
在不破坏主任务解释的前提下，额外提供教育场景专项子基准，方便对模型的泛化能力做更细致分析。

### 7.6 标注目标清晰且任务边界明确
本提交版评测集没有把多种不兼容的标签体系强行揉成一个“统一答案空间”。

- 主 OCSR 核心基准统一使用 `canonical_smiles`
- 教育场景专项子基准统一使用 `ssml_normed`

这样的设计能够避免“同一张图存在多个等价但不可直接横比的标签表示”所带来的歧义，保证评测结果更加稳定、可复核、可解释。

---

## 8. 使用建议

1. **主结果**：优先报告 `canonical_smiles_main_v1` 的结果；
2. **专项结果**：单独报告 `edu_chmec_ssml_normed_test_v1` 的结果；
3. **不建议**直接把两个子基准混成一个单总分；
4. 如果需要对外展示综合能力，应使用“主 OCSR + 教育场景补充结果”的方式进行解释。

---

## 9. 标注准确性与质量控制概览

本评测集在构建时，重点遵循了“单样本单目标、目录可复现、标签口径隔离、正式提交内容收口”的原则。

### 9.1 标注目标统一
- `canonical_smiles_main_v1`：每张图只保留一个 `canonical_smiles` 主标签；
- `edu_chmec_ssml_normed_test_v1`：每张图只保留一个 `ssml_normed` 主标签。

### 9.2 结构性错误控制
当前正式提交目录中已经完成以下结构性质量控制：

- 清理无关候选层、临时目录与中间过程文件；
- 删除 `._*` 等无效图片文件，避免评测时被错误读取；
- 保证每个正式子基准均具有独立的 `annotations/` 和 `images/`；
- 保证 `stats.json` 与目录结构、样本规模一致；
- 保证主 OCSR 与教育场景标签体系隔离，不发生主任务口径污染。

### 9.3 当前质量判断
从当前目录、标签文件和统计结果来看，本提交版已经具备“**无明显结构性标注错误**”的基本条件，能够作为正式提交版评测集使用。

### 9.4 后续可增强方向
若后续需要进一步提升“标注准确性”这一项的说服力，建议补充少量可视化抽检页，对不同来源与难度的样本展示“图像—标签”对应关系。

---

## 10. 难度分布合理性说明

本评测集并未仅使用单一来源、单一难度或单一视觉条件的数据，而是通过两个子基准共同覆盖：

1. 标准 OCSR 公开基准场景；
2. 真实世界补充场景；
3. 教育场景专项样本；
4. 不同难度与视觉条件变化。

在主 OCSR 核心基准中，样本包含 `medium / medium_hard / hard` 等不同层级；同时在真实世界补充部分又覆盖了 `photo / scan / page_level / degraded_scan / handwritten / journal_fig / multi_grid` 等多种场景标签。

这种设计比单一清洁 benchmark 更接近真实垂域任务中的数据分布，有助于更全面地评估模型在不同难度与不同视觉条件下的鲁棒性与泛化能力。

---

## 11. 一句话总结

本评测集是一个**规模充足、结构清晰、任务边界明确、可直接提交**的 OCSR 正式评测集集合：

- `canonical_smiles_main_v1` 负责主 OCSR 基准；
- `edu_chmec_ssml_normed_test_v1` 负责教育场景专项补充；
- 二者统一提交，但分别解释，不混成一个不清晰的总分。
