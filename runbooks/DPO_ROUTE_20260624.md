# DPO 路线（SFT 之后）

这条路线只处理一件事：把现有推理候选整理成偏好对，再拿去做第二阶段对齐。

前提很明确：

- `SFT` 已经做过；
- 候选重排做过；
- hard negative 也试过；
- 这些手段的边际收益已经不稳定。

所以这里不再继续堆同类 SFT，而是把“同一张图上的更好答案”和“更差答案”拉开。

## 为什么这次用 DPO

当前任务有稳定的 gold 答案，问题不在“没有监督”，而在“模型会出候选，但优先级不稳”。

DPO 适合放在这里的原因是：

- `chosen` 可以直接用 gold 的 `canonical SMILES`；
- `rejected` 可以用同图同 prompt 下的错误候选；
- 目标不是让模型学会回答，而是让模型更倾向于输出更对、更稳的那个答案。

不建议把下面这些混进同一条 DPO 线：

- `ssml_normed`
- `chemfig`
- LaTeX
- 其他非 `canonical SMILES` 口径

只要标签空间不统一，DPO 也只会把偏好学歪。

## 这条线的输入是什么

1. 先跑推理，并保留候选：

```bash
python scripts/infer_ocsr_transformers.py \
  --model-dir <model_dir> \
  --benchmark-jsonl <benchmark.jsonl> \
  --project-root . \
  --output-jsonl <pred.jsonl> \
  --prompt-list-file configs/prompt_rank.txt \
  --num-beams 4 \
  --num-return-sequences 4 \
  --tta-preset light \
  --save-candidates \
  --device cuda \
  --torch-dtype bfloat16
```

2. 再把预测结果和 benchmark 合成偏好对：

```bash
python scripts/build_ocsr_dpo_preferences.py \
  --project-root . \
  --benchmark-jsonl <benchmark.jsonl> \
  --prediction-jsonl <pred.jsonl> \
  --output-jsonl <dpo_pairs.jsonl> \
  --report-json <dpo_report.json>
```

## 偏好对怎么定

构造规则保持简单：

- `chosen`：gold 的 canonical SMILES；
- `rejected`：同一条样本里最像样、但仍然错的候选；
- 如果没有干净的 rejected，就直接丢掉这条；
- 如果 gold 不是 canonical SMILES，或者根本不能稳定解析，也丢掉。

这样做的目的不是凑数量，而是保证偏好对是干净的。

## 建议的来源顺序

优先顺序建议是：

1. `canonical_smiles_main_v1`
2. `ocsr_realworld_mixed_eval_v1p1`
3. 仍然保持 `canonical SMILES` 口径的弱域补充集

不建议一上来把所有来源揉成一锅。

## 训练前先看什么

先看 `dpo_report.json` 里的这几项：

- `usable_pairs`
- `usable_by_source`
- `usable_by_negative_kind`
- `usable_by_target_field`

如果某个 source 一下子占太多，先限额，不要让 `uob/uspto` 把其他来源压没了。

## 这条线的真实定位

DPO 在这里不是主线起点，也不是替代 SFT 的东西。

它的定位是：

- SFT 负责把模型拉到任务边界内；
- 候选重排负责看见候选差异；
- DPO 负责把“更好的那个候选”固定下来。

如果后面远端环境里没有现成 DPO trainer，那也没关系，先把这份偏好对数据留好，后续可以直接接训练器。
